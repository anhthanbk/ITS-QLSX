# UI/UX Rules

- Use the project's existing design system.
- Prefer consistent spacing, typography, controls and interaction patterns.
- Every async screen should have loading, empty and error states.
- Tables must remain usable with realistic data volumes.
- Forms should clearly show validation errors and save states.
- Confirm destructive actions.
- Preserve responsive behavior.
- Check keyboard accessibility and semantic HTML.
- Do not redesign unrelated screens during a feature task.
- Verify the final UI in a real browser.
